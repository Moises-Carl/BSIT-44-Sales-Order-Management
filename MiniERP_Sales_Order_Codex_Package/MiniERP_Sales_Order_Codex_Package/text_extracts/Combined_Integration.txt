Mini-ERP: Integration of System 1 (Catalogue)
and System 2 (Sales/Order)
Integration specification — unified database design, reconciliation decisions, business
rules, and handoff contract.


1. Purpose and Scope
This document merges the Product/Catalogue Management design (System 1) and the
Sales/Order Management design (System 2) into one relational schema. It targets MySQL
8.0.16 or later (or MariaDB 10.2.1 or later), because older versions parse CHECK
constraints but do not enforce them.

Included: Category, Product, Seller, SellerOffer (System 1); Customer, SalesOrder,
OrderItem, OrderStatusHistory (System 2).

Not included yet: Inventory, Billing, Delivery. The Sales design references them, but their
tables will be added after Systems 3 to 5 are reviewed.

   -- ===== INTEGRATION VIEW =====
   -- The single definition of "can this offer be ordered right now?"
   CREATE OR REPLACE VIEW v_orderable_offer AS
   SELECT o.offer_id, o.seller_id, o.product_id, p.product_name, o.selling_price
   FROM seller_offer o
   JOIN product p ON p.product_id = o.product_id
   JOIN seller s ON s.seller_id = o.seller_id
   WHERE o.offer_status  = 'active'
        AND p.product_status = 'active'
        AND s.seller_status = 'active';


All foreign keys use the default ON DELETE NO ACTION behaviour, so referenced rows
cannot be deleted. This supports the retention rule in both documents.

7. Integration Flow (Catalogue to Sales)
 1. Browsing. Sales reads v_orderable_offer to show what customers can buy.
 2. Adding to a draft. Sales inserts an order_item with the offer_id, seller_id, quantity, and
    the price the customer is seeing. If the offer is already in the draft, increase its
     quantity instead.
 3. Submitting. In one transaction:
           Re-check each item against v_orderable_offer . Reject inactive items and name
           them.
           Compare each item's current selling_price to the draft price. If any differ, stop and
           ask the customer to accept.
           Write the final unit_price_at_order and product_name_at_order, recalculate
           order_total, set order_status to pending_stock, and add a status-history row.
 4. After submission. Sales no longer depends on the catalogue for that order. Everything
     it needs is in the snapshot.
